# 子代理与提及

Aeloon Desktop 0.0.26 仍可连接旧版 Runtime 进行普通对话。子代理委派、子代理目录和工作区
文件提及需要 Runtime 0.1.10 或更高版本。如果 `fs.search` 不可用，Desktop 会保持对话可用，
但不显示文件候选项。

## 使用提及

在对话输入框中输入 `@`，即可搜索可用代理和文件；也可以用命名空间只搜索一种来源：

```text
@agent:researcher 对比这两种实现
@file:src/main.ts 解释这个入口
@file:"docs/My File.md" 总结这份文档
```

可使用鼠标，或方向键加 Enter 选择结果。Desktop 会插入稳定的命名空间文本；路径包含空格、
引号或反斜杠时会自动使用 JSON 引号。文件候选只来自当前对话已授权的工作区。

内置 `researcher` 是只读研究代理，会返回带文件和行号的证据。其他代理需先被发现，并启用
**设置 → 子代理 → 加载子代理**；修改后的开关作用于新操作。

## 定义子代理

每个代理使用一个 Markdown 文件，放在以下任一位置：

- Runtime 数据目录：`<runtime-data-dir>/agents/*.md`，作用于该 Runtime 安装。
- 工作区：`<workspace>/.aeloon-runtime/agents/*.md`，作用于该工作区。

配置的额外资源根目录也可以包含代理 Markdown 文件。定义由 YAML frontmatter 和正文指令组成：

```markdown
---
name: reviewer
description: 检查改动的正确性以及遗漏的测试。
tools: [read, grep, find, ls]
---

检查指定改动，并按严重程度返回带文件和行号的发现。
```

`description` 必填。`name` 默认使用文件名主干，可包含字母、数字、句点、下划线和连字符。
`tools` 可省略；省略表示请求使用父代理当前可用的工具。Runtime 数据目录或额外资源根目录中的
定义还可指定 `model`；工作区定义会有意忽略 `model`，避免检出的项目自行选择 Provider 模型。

## 安全边界

- 子代理只能获得其请求工具与父代理当前工具的交集；定义文件无法授予父代理不具备的能力。
- 子代理不能再次委派子代理，每个任务的进度和结果输出都有上限。
- 文件搜索不会越过已授权工作区，会跳过符号链接，在可用时遵循仓库忽略规则，并限制超时、
  候选数量和结果数量。
- 代理文件和提及不会包含或暴露 Provider 凭据；模型访问仍由 Runtime 的 Provider 配置和凭据
  处理机制控制。
- 工作区定义属于项目内容，启用前应像审查其他项目指令一样审查它们。关闭**加载子代理**后，
  已发现的代理不会提供给新操作。
